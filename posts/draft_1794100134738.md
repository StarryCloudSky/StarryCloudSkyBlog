动态规划在算法设计中算是最高难度的那一档，令无数小白闻风丧胆。同时动态规划又是最优雅迷人的算法，只要是算法类竞赛，必然有动态规划类型的题目。什么是动态规划？什么是状态转移？什么是重叠子问题？今天我们就来详细探讨一下动态规划，看完后保证你不再害怕动态规划类的题目(手动doge)。

什么是动态规划？动态规划是运筹学中最优化问题的一个算法，因此它一般被用来求最值问题。比如“最长子序列”、“最小编辑距离”、“零钱兑换最少硬币数”。同时动态规划是一种典型的用空间换时间的算法，这个在下文有所体现。动态规划能解决的问题满足3个条件：

> 1.有明确的状态
>
> 2.有重叠子问题
>
> 3.有最优子结构

解决动态规划问题的步骤也很简单：

> 1.定义问题的状态
>
> 2.设置初始状态
>
> 3.列出状态转移方程
>
> 4.执行状态转移

如果你去看那些动态规划的题解，得到的代码模板基本就是这样：

```cpp
// 初始化
dp[0][0][...] = 某个值;
# 进行状态转移
for (状态1 : 状态1的所有取值) {
    for (状态2 : 状态2的所有取值) {
         for ...
            dp[状态1][状态2][...] = 求最值(选择1，选择2...)
    }
}
return dp[某个值];
```

在动态规划问题中，困难的往往是明确问题的状态和如何找出状态转移方程。这两个步骤解决了那么动态规划问题基本就被解决了。

相信大部分人看到这里一脸懵b，状态是啥？重叠子问题是什么？最优子结构又是什么？状态转移方程是啥玩意？且听我慢慢道来。

状态通俗地来讲就是对当前某个局面的描述，比如你想从A地走到D地，中间有B地和C地，相邻两地之间有很多条路程长短不一的路径供你选择，那么在你从A地到D地的过程中，目前处在哪个地方就是这个问题的局面，也就是这里所说的状态了。你处在不同地点还没到目的地，需要选择一条尽量短的路走，这个就叫状态转移，因为它改变了你当前的局面，即走到了下一个地点。

### 重叠子问题

以下用斐波那契数来说明什么是重叠子问题，虽然这个例子并不是动态规划的问题，因为它求的不是最值嘛，但是它却将重叠子问题展示地淋漓尽致，是非常好的入门素材。

‍

![](https://bu.dusays.com/2026/11/08/6aefd032a702d.png)

传送门如下：[509. 斐波那契数 - 力扣（LeetCode）](https://leetcode.cn/problems/fibonacci-number/description/)

解决这个问题相信对大家来讲非常简单，学校老师讲递归的时候都讲烂了，我们可以很快写出递归解法：

```cpp
// 计算第n项斐波那契数
int fib(int n) {
    // 边界条件，直接返回边界值即可
    if (n == 0 || n == 1) {
        return n;
    }
    // 往下递归地计算
    return fib(n - 1) + fib(n - 2);
}
```

但是这个暴力递归解法效率极低，数字n一旦大起来就会超时，为什么呢？我们把计算过程的递归树画出来便知。

‍

![](https://bu.dusays.com/2026/11/08/6aefd435a75da.png)

在这里f(n)表示计算第n项斐波那契数。要计算第18项斐波那契数，我只需要算出第17项和第16项，计算第17项只需要计算出第16项和第15项...。在这个计算过程中，我们发现存在着大量重复的计算，比如上图中第16项的值已经在计算第17项的时候算过了，结果在计算第18项的时候又花时间算了一遍。这就是重叠子问题，一个问题能被分解为若干个子问题，但是在原问题解决的过程中子问题被重复计算，导致算法时间复杂度爆炸。

说白了我们的优化方向就是减少重叠子问题的计算，也就是对递归树做剪枝操作，怎么优化呢？用一个备忘录记录每一次计算得到的结果就行了嘛，下一次遇到问题相同的重复计算的时候我直接去备忘录里查那个结果。这便是记忆化搜索，在搜索过程中先查备忘录，如果备忘录里没有记录，那就去计算，备忘录里有记录说明这个问题已经被计算过了，直接返回备忘录里的值就行了。

有了上面的优化思路，我们的代码就可以写成这样：

```cpp
    int fib(int n) {
        vector<int> memo(n + 1, -1);
        return dp(memo, n);
    }

    int dp(vector<int>& memo, int n) {
        // 边界条件，直接返回边界值即可
        if (n == 0 || n == 1) {
            return n;
        }
        // 先去备忘录里查找
        if (memo[n] != -1) {
            // 备忘录里有记录，直接返回值
            return memo[n];
        }

        // 备忘录里没有，说明是第一次计算
        int res = fib(n - 1) + fib(n - 2);
        // 将结果存在备忘录中
        memo[n] = res;
        return res;
    }
```

经过上述优化后，递归树被我们成功剪枝，免除了大量重复计算。同时我们发现，最终答案的计算依赖于递归边界条件的返回，也就是“归”的过程，“递”的过程做的只不过是不断将问题做拆解，拆到无法再拆为止。得到最小问题的答案后，依靠memo数组边“归”边记录。

‍

### 自上而下与自下而上

我们依靠递归自上而下的对原问题的不断拆解得到子问题，最终依靠最小子问题的答案和memo数组向上传递子问题结果。上面也提到了最终答案依赖于递归边界条件的返回，就是那个“归”的过程，而“归”的过程做的就是fib函数一直接收子问题的返回值，然后再返回他自己的返回值，但是我们设置了memo数组记录了每个子问题的值，因此“归”的过程实质上就是memo数组不断自下而上返回值的过程。因此我们可以不需要自上而下“递”的过程，只需要自下而上的“归”，直接给memo数组设置边界初始值，然后迭代到第n项。这就是自下而上的递推。

改写代码如下：

```cpp
int fib(int n) {
    if (n == 0 || n == 1) {
         return n;
    }
    vector<int> memo(n + 1);
    // 设置边界值
    memo[0] = 0;
    memo[1] = 1;
    for (int i = 2; i <= n; i++) {
        memo[i] = memo[i - 1] + memo[i - 2];
    }
    return memo[n];
}
```

这就得到了我们最常见的动态规划迭代解法，只不过把数组名改成dp就行了。

memo数组在这里的含义很明确了----第i项斐波那契数的值，这就是所谓的“定义问题的状态”。对memo数组的初始化就是设置初始状态，斐波那契数列第一项和第二项都是1嘛。我们是通过memo[i] = memo[i - 1] + memo[i - 2]得出其他项的值，这就是状态转移方程，说白了就是一个很自然的递推式，我们依靠这个递推式进行“第i项斐波那契数的值”这个状态的转移。

至此，相信大家对于什么是重叠子问题，什么是状态和状态转移方程已经有了一个初步了解。所谓动态规划，就是我们在暴力递归计算所有子问题的解的时候时间复杂度太高，用备忘录消除重叠子问题，心情好的话改写成自下而上的递推。
